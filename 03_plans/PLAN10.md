## Goal

基準ペインの右にペインが無い場合でも、**ワークスペース内に markdown タブのあるペインが既にあれば、
分割せずそこにタブで開く。** 監視をどのペインで起動しても、ビューアが 1 か所に集まる。

## 背景（`RESULT9` の V5）

```
作成前                                    作成後
┌────────┬─────────────────┐            ┌────────┬──────────┬─────────┐
│ Claude │ 監視 (terminal) │            │ Claude │ 監視     │ 新しい  │
│        ├─────────────────┤     →      │        │          │ 分割    │
│        │ markdown        │            │        ├──────────┴─────────┤
└────────┴─────────────────┘            └────────┤ markdown           │
                                                 └────────────────────┘
```

監視が右上のペインで動いていたため、基準ペイン（= 監視のペイン）の右にペインが無く、PLAN6 の
規則どおり基準ペインが分割された。下の markdown ペインは「右」ではないので候補にならなかった。

## 現在の動作（PLAN6、実装済み）

ファイルを開くたびに `cmux tree --json` でレイアウト（二分木）を読み、次の順で決める:

1. 基準ペイン: 監視は起動したターミナルのあるペイン（`--surface` で上書き）、hook / CLI は
   `CMUX_SURFACE_ID` のあるペイン。
2. 基準ペインの右側の部分木があれば、その中で markdown タブのあるペイン（無ければ左上のペイン）に
   `cmux open <path> --pane <ref> --no-focus` でタブを追加する。
3. 右側が無ければ、`cmux markdown open … --surface <基準ペインで選択中の surface>` で基準ペインを
   右に分割する。
4. レイアウトを読めない・基準ペインが見つからないときは、従来の分割にフォールバックする。

関数: `choose_target(layout, panes, pane_ref)` が 2 の開き先（または None）を返す。

## 変更

手順 2 と 3 の間に 1 段追加する:

> **2.5** 右側が無いとき、ワークスペース全体のレイアウトの葉を `children[0]` 優先の深さ優先
> （左上から）で並べ、**基準ペイン以外で、markdown 型の surface を持つ最初のペイン**を探す。
> あれば、そこに `cmux open <path> --pane <ref> --no-focus` でタブを追加する。無ければ手順 3（分割）。

| # | 要件 |
|---|---|
| R1 | 右側にペインがある場合の動作（手順 2）は変えない。右側のペインが markdown を持たず、別の場所に markdown ペインがあっても、右側を使う |
| R2 | 基準ペイン自身は 2.5 の候補にしない（監視や Claude のターミナルと同じペインにタブを足すと、ターミナルが隠れる） |
| R3 | 候補は基準ペインの左・上・下のどこにあってもよい |
| R4 | `choose_target` を拡張し、純粋な関数のままテストする。監視・hook・CLI の 3 モードに同じく効く |
| R5 | 監視の stdout の表記は今のまま（`(tab in pane:…)` / `(new split)`）。フォールバック、hook / CLI の約束（常に exit 0、stdout なし）も変えない |

### 既知の挙動（対象外）

- markdown ペインが複数あるときは、左上に近いものが選ばれる。
- ビューア以外の用途で markdown タブを開いているペインも候補になる。
